# Group 5 (Places) → all groups

> Sent to every group. Proposes the broker rule that the report's Reliable delivery describes. It leaves out that a consumer must bind its queue before the first message it needs is published; `drafts/g5-to-all.md` adds that.

*For everyone: how we use the broker*

G3 told us G4 runs RabbitMQ. We propose one rule for all groups:

- Each group that publishes declares one durable topic exchange named after itself. Ours is `places`.
- The routing key is the message type, which is also in the `type` field of the body. Ours are `BookingConfirmed` and `BookingCancelled`.
- Publishers send persistent messages and wait for the broker's confirmation.
- Each group that consumes declares its own durable queue, binds it by routing key, and acknowledges a message only after handling it.

This gives at-least-once delivery: no message is lost, but one can arrive twice, so consumers must ignore repeats. For our messages, use `bookingId` for that.

Also for everyone: `promoterId` in our messages is the Promoter's *user id*, the same value the Gateway sends as `X-User-Id`.
