# Revision history {.unnumbered}

Wiegers and Beatty ask that each circulated version of a requirements document carry a revision history [@wiegers2013, ch. 27]. Each version of this report is a tag in the group's repository, and the title page names the version the PDF was built from. Table \ref{tab:revisions} lists each version, when it was released, what changed and why. Who made each change is in the repository's history.

| `delivery-1` | 2026-11-18 | Billing (G3) cancels a Booking's bill on *Booking cancelled* if the Promoter hasn't paid it, and refunds no paid bill (Messaging and collaborations, Open points). Question L5 is answered. Places no longer receives *Rating changed* from Reviews (G1): every five minutes it reads every Venue's Rating in one call, and a Venue missing from the answer loses its Rating (Messaging and collaborations, System operations). The report no longer says that Promoters rate Venues, since who may rate is Reviews' rule (Application requirements). Questions L6 and L13 are answered. Events replaces a Booking with a Rebooking, one Booking request that names the Booking it replaces, instead of cancelling and booking again (Application requirements, System operations, REST API, `openapi.yaml`); *Booking confirmed* carries `replacesBookingId`, and Billing carries a paid bill over to the new Booking (Messaging and collaborations, Open points). Billing keeps one bill per Booking id and stores `venueManagerId` on each bill (Messaging and collaborations). Paying the Venue Manager a Booking's amount is out of scope (Application requirements, Open points), and question L9 is answered. L7 notes that G3 binds Billing's queue to `places` (Open points). Events may read Venues with `getVenue` and `searchVenues` (Application requirements, System operations, REST API, `openapi.yaml`). *Venue updated* is out of scope for delivery 1 (Application requirements, Open points). G2 asked how Events recovers a Booking if it fails between Places' `201` and saving its Event: sending the request again is rejected, and without the Booking's id Events can't cancel it.
